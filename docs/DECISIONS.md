# Decisions

Format: **ID, decision, why, consequence.** Anything that changes a "fixed decision" from the
brief (Part C) is marked ⚠ and was asked about first. None so far.

## Phase 0

**D-001 Money is integer paise.** Floats cannot represent 0.1 exactly (`0.1 + 0.2 = 0.30000000000000004`),
so a ledger built on floats drifts. ₹349 is stored as `34900`. All `*_paise` columns are `INT`
with CHECK constraints; the shared zod `paiseSchema` rejects non-integers.

**D-002 Phase 0 migrates foundation tables only.** Identity, catalog, price bands, admin/audit,
config, flags, minimum wage. Domain tables (requests, jobs, wallet, ...) arrive in the phase
that builds and tests them. A schema nobody exercises is untested guesswork. Part E is still the
target; nothing is dropped.

**D-003 "Ranger" is the user-facing word; `WORKER` stays internal.** The DB enum, table names
(`worker_profiles`) and routes (`/worker/*`, from Part F) keep the neutral name so we do not
rename the whole backend for a branding word. Every string a person can read says Ranger
(UI copy, notifications, emails, PDFs). Enforced by tests: `USER_FACING_ROLE_LABEL` and a
mobile i18n test that fails if any locale contains "worker". Notification templates (Phase 5)
get the same test.

**D-004 Version pins.** NestJS **11** (12 is ESM-only and breaks the CommonJS + Jest setup),
Prisma **6** (7 replaces the config model), zod **3**. Expo SDK 57 / React Native 0.86 as
generated by `create-expo-app`. Revisit deliberately, not by accident.

**D-005 Local Postgres on host port 5433.** Windows machines often already run Postgres on 5432.

**D-006 Redis is an accelerator, not the source of truth.** Presence, geo index, locks and rate
limits live there, but every correctness guarantee (e.g. double-accept prevention) is also
enforced in Postgres. `/health/ready` reports `degraded` (still HTTP 200) when Redis is down and
`unavailable` (HTTP 503) only when Postgres is down. Tested.

**D-007 Price band cluster = first 3 digits of the PIN code.** It is the postal sorting district,
needs no lookup table, and gives neighbourhood-scale groups. Fallback chain and threshold
(`price_band_min_sample`, default 10) live in `system_config`, so ops can tune them without a deploy.
Seeded default bands have `sample_size = 0` and are returned with `isSeededDefault: true`.
**They are placeholders that ops must review before launch** (see RUNBOOK).

**D-008 Raw SQL appended to Prisma migrations.** Prisma cannot express PostGIS types, GIST
indexes, expression-based unique indexes, CHECK constraints or triggers. The extension gets its
own first migration; the foundation migration = generated SQL + a clearly marked raw section.

**D-009 Health and metrics are unversioned** (`/health/*`, `/metrics`): orchestrators and
Prometheus expect stable paths. Business routes are `/v1/...`.

**D-010 Dev object store: `bitnamilegacy/minio`.** MinIO stopped publishing images to Docker Hub
and Quay. This image is a real MinIO build, used for local dev only. Production uses AWS S3 or
Cloudflare R2 through the same S3 client, so nothing MinIO-specific leaks into app code.

**D-011 pnpm `node-linker=hoisted`.** Metro (Expo's bundler) does not work with pnpm's default
symlinked layout.

**D-012 Sandbox adapters are refused in production.** `NODE_ENV=production` with any
`*_MODE=sandbox` fails at boot. Live mode requires its credentials. This makes "shipped fake
payments" impossible by accident.

**D-013 Rate limiter is in-memory in Phase 0.** Fine for one instance. Phase 1 replaces it with
Redis-backed limits (per phone and per IP for OTP) so limits hold across instances.

**D-014 Admin app (Next.js) starts in Phase 1**, alongside the KYC queue that gives it a first
real screen. Scaffolding an empty Next app now would be a dummy shell.

**D-015 Cursor pagination, not OFFSET.** Helper in `packages/shared/src/pagination.ts`, tested.
